# Первая загрузка: диагноз и исправление

## Что происходит на самом деле

Данные **реально загружаются** — это не глюк. Приложение читает канал Telegram «My area» и строит локальный список файлов/миниатюр. На машине с установленной версией 1.1.11 в кэше было 16 135 файлов, 12 папок и 1 372 соответствия файл→папка.

Почему выглядело как «ничего не грузится»:

1. Splash показывает декоративную анимацию, а не реальный прогресс (`SplashScreen.tsx`), после него — ещё 3 секунды `DuckSplash` по таймеру.
2. `telegram:reconnect` блокировал UI проверкой бота через BotFather (до 15 с на ответ) и синхронизацией папок.
3. При поиске синхронизирующего сообщения папок `loadFoldersFromChannel()` не находил его поиском и уходил в ручной скан до 12 000 сообщений — без прогресса и логов.
4. Полное сканирование канала (`listFiles`) идёт батчами по 200 сообщений с паузами, затем follow-up проверки (verify/heal/mdfind) снова без прогресса.
5. Событие `files:sync-progress` уже существовало в preload, но рендерер на него **не подписывался**.
6. Дополнительно: старый конфиг (`rodjercloud-prefs.json`) держал `autoSync.enabled=true` для `~/Downloads`. При запуске приложение само начало загружать в облако большой `.mkv` (9 частей, ~18.6 ГБ), хотя пользователь ничего не инициировал.

## Что изменилось

- **Режим просмотрщика.** Автосинхронизация больше не запускается при старте, даже если в старом конфиге `enabled=true`; флаг сбрасывается в `false`. Сохранённая очередь загрузок на диске очищается вместо автоматического возобновления. Загрузка в облако — только явным действием пользователя.
- **Быстрый вход.** Проверка/создание бота и чтение структуры папок больше не блокируют `telegram:reconnect`: тяжёлые операции уходят в фон. Если локальные папки уже есть, канал при открытии «Мои файлы» не сканируется.
- **Реальный прогресс.** `TelegramService` рассылает события `cloud:load-progress` с этапом, количеством прочитанных сообщений, числом файлов, номером пакета и процентом (если известен). `App.tsx` показывает `CloudLoadingScreen` в стиле приложения (градиент `--accent-gradient`, стеклянная карточка, Lottie-утка) вместо фиктивного таймера. Кнопка «Открыть файлы» позволяет пропустить ожидание.
- **Пакетная подгрузка.** Список файлов сохраняется в `file-cache.json` каждые 3 пакета; рендерер получает `files:changed` по мере чтения, поэтому файлы и миниатюры появляются сразу, а не после полного сканирования.
- **Надёжность.** Splash запрашивает `cloud:load-state`: если синхронизация уже завершилась до монтирования компонента, экран сразу закрывается. Есть safety-таймер 12 с, чтобы progress-экран никогда не блокировал UI.

## Проверка

```bash
npm install --legacy-peer-deps
npm run build
npx tsc --noEmit
```

В логе установленной версии признаки старой проблемы:

```
search miss, falling back to history scan
[upload] stage:sendFile-begin ... part=1/9
```

После исправления загрузки в облако при старте быть не должно, а рендерер получает этапы «Подключение → Канал → Папки → Файлы и миниатюры → Сверка».
